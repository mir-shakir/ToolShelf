What is a text diff?

A text diff compares two versions of a document and highlights the differences — which lines were added, removed, or left unchanged. It's one of the most foundational tools in software engineering, used every day in code review, config auditing, and content editing.

Side-by-side vs unified view

Side-by-side shows the two documents in parallel columns with added/removed lines aligned. It's easier to scan when you want to understand the shape of a change.

Unified (a.k.a. patch view) inlines the changes with + and - prefixes and @@ -a,b +c,d @@ hunk headers. It's the format git apply and patch(1) understand, so the output is directly usable in automation.

How LCS-based diffing works

The classic algorithm is based on the longest common subsequence (LCS). Given two sequences of lines, LCS finds the longest ordering of lines that appears in both. Anything not in that common subsequence must have been inserted on one side or deleted on the other.

Example:

Original: a b c d e
Changed:  a x c d
LCS:      a   c d
Edits:    -b, +x, -e

Real-world diff tools (like git diff) use Myers' refinement for speed, but the output is conceptually the same. This tool uses plain LCS; see the FAQ for size limits.

Use cases

  • Code review — compare a snippet against the main branch before pushing.
  • Config drift — spot changes in YAML / JSON / TOML config files.
  • Contract / document redlines — track edits in legal or spec documents.
  • SQL schema comparison — see what's changed between two pg_dump outputs.
  • Localization QA — audit translated strings against the source language.

Why this tool runs on demand, not live

Line-level LCS has O(n·m) complexity. On large inputs, running it on every keystroke would freeze your browser. The Compare button is a deliberate UX trade-off — the tool stays fast and responsive even with tens of thousands of lines.

FAQ

How does the diff work?

LCS at the line level, then an edit script (equal/insert/delete).

Is my text sent to a server?

No. Everything runs in your browser.

What is the line limit?

100,000 lines per side, with a product cap of 10 million to protect your browser.

What does "ignore whitespace" do?

Collapses runs of whitespace and trims lines before comparing. Original text is still rendered.

Why aren't words highlighted inside changed lines?

This release is line-level only; word-level diffing is on the roadmap.

Why isn't the diff live as I type?

Performance: LCS gets expensive fast. On-demand keeps the UI snappy.

Can I export as a patch?

Yes — Copy or Download produces standard unified-diff output.

Does it support binary files?

No. Plain text only.
